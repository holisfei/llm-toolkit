## 让模型返回结构化输出
大模型返回 JSON 有两类失败：格式 vs 语义。 语义失败沉默，所以更危险。
"成功率"必须先定义"成功"和"分母"。 否则数字会自己骗自己。

```json
{
  "name": "holis",
  "uid": 100000,
  "signature": "生活不止眼前的苟且"
}
```
```json
{"name":"Holis","uid":100000,"signature":"生活不止眼前的苟且"}
{"name":"holis","uid":100000,"signature":"生活不止眼前的苟且"}
{"name": "holis", "uid": "100000", "signature": "生活不止眼前的苟且"}
```

## 接收结构化输出

让模型能够正确的输出想要的结构化json，从以下两点考虑：
- schema(model) 层：字段可以是 str | None = None —— 让"诚实地说没有"成为合法选项
- prompt 层：明确写"原文中找不到的字段，必须返回 null，禁止编造或填占位符" —— 告诉模型何时用这个选项

光从schema加约束，不能组织llm返回垃圾数据，因为llm会基于错误信息，强行符合表面的验证规则，实际语意还是错误的

错误重试：对于原信息有的值没有提取到需要重试，失败后，prompt需要凭借上一次的失败输出，和报错提示，一并给llm让其再次生成，对于原始信息根本不存在而让llm为了符合验证规则去重试，这种情况不需要重试，即使重试了，最后语意上也是失败的
