# 结构化输出

## 让模型返回结构化输出
大模型返回 JSON 有两类失败：格式 vs 语义。 语义失败沉默，所以更危险。
"成功率"必须先定义"成功"和"分母"。 否则数字会自己骗自己。

```json
{
  "name": "holis",
  "uid": 100000,
  "signature": "生活不止眼前的苟且"
}
```
```json
{"name":"Holis","uid":100000,"signature":"生活不止眼前的苟且"}
{"name":"holis","uid":100000,"signature":"生活不止眼前的苟且"}
{"name": "holis", "uid": "100000", "signature": "生活不止眼前的苟且"}
```

## 接收结构化输出

让模型能够正确的输出想要的结构化json，从以下两点考虑：
- schema(model) 层：字段可以是 str | None = None —— 让"诚实地说没有"成为合法选项
- prompt 层：明确写"原文中找不到的字段，必须返回 null，禁止编造或填占位符" —— 告诉模型何时用这个选项

光从schema加约束，不能阻止llm返回垃圾数据，因为llm会基于错误信息，强行符合表面的验证规则，实际语意还是错误的

错误重试：对于原信息有的值没有提取到需要重试，失败后，prompt需要凭借上一次的失败输出，和报错提示，一并给llm让其再次生成，对于原始信息根本不存在而让llm为了符合验证规则去重试，这种情况不需要重试，即使重试了，最后语意上也是失败的

## Anki

Q: 把 schema 约束加严(如 min_length=2)能阻止模型返回垃圾吗?为什么?

A: 不能。模型会用"恰好满足约束的垃圾"应对(俩空格满足 min_length=2)。约束是表面的,语义是底层的;你无法用结构约束表达"这个值必须真实存在于原文"。
Q: 模型返回 JSON 的两种失败模式?各自的被发现成本?

A: ①格式失败(markdown 包裹/非法 JSON)→ 解析层立刻报错,大声,能发现。②语义失败(类型偷偷变、字段是垃圾)→ 解析通过,沉默,流进下游才暴露甚至永不暴露。语义失败危险 10 倍。
Q: 模型提取字段失败时,什么情况该重试、什么情况重试有害?

A: 信息在原文里有、只是没提取对 → 重试能救(把错误塞回 prompt 让它自修)。信息原文根本没有 → 重试只会逼模型编造,应给"诚实失败出口"(字段设 | None + prompt 明确"找不到返回 null,禁止编造")。
Q: 为什么"成功率 X%"单独说是危险的?

A: "成功率"含两个未定义维度:分母是什么、"成功"如何定义。同一份数据,定义不同能得出 42%/50%/85%。报数字前必须先定义这两点。
